# Grafana for Index

Provisioning files for the Grafana service on Railway (project Index, environment main). Grafana 13.x, file provisioning, no plugins.

## Datasources

| Name | uid | Role | Data |
| --- | --- | --- | --- |
| Index | `index-pg` | `grafana_ro` | the `analytics` views on the production database |
| Index Trace | `index-trace` | `grafana_trace_ro` | the `trace` schema on a Neon dev branch (`trace-proto`) |

`grafana_trace_ro` is read-only and has no access to `public` or `analytics`. Its password is read from `TRACE_PG_PASSWORD`; the Index password from `INDEX_PG_PASSWORD`. Neither is in this repository.

## Dashboards

- Folder Index: `dashboards/*.json` (activation, negotiation, opportunity, retention, supply), generated by `gen-index-dashboards.py`.
- Folder Index Trace: overview, drill-down (variable `interaction`) and adversarial boards, generated by `gen-trace-dashboards.ts` (`bun ops/grafana/gen-trace-dashboards.ts <outdir>`).

The Index Trace boards show real negotiation text from a pseudonymized dev branch. They sit behind the Grafana login; anonymous access is off.

## Delivering the files to Railway

The service runs the stock Grafana image. The provisioning files are packed into a tar.gz, base64-encoded and split into 500 character chunks, because the variable API rejects long values.

```bash
ops/grafana/build-bundle.sh /tmp/gb
```

The script writes `bundle.tgz`, `bundle.b64` and `chunks/TR_00..TR_NN`, and prints the start command. The tar is deterministic, so the same sources give the same sha256.

1. Set each chunk as a service variable (`TR_00`, `TR_01`, ...) and `TRACE_PG_PASSWORD`.
2. Set the printed start command.
3. Redeploy.

The start command reassembles the chunks, checks the sha256, and extracts into `/`. If the check fails it prints `bundle-check-failed-using-previous` and unpacks the earlier Index-only bundle held in `IDX_00..IDX_10`, so a mistyped chunk cannot leave the service without dashboards. It always ends with `exec /run.sh`. Once the new bundle has run cleanly for a while, the `IDX_` variables and the fallback can be removed.

A healthy deploy logs `/tmp/b.tgz: OK` and then `finished to provision dashboards`.

## Notes

- Dashboards are written under `/var/lib/grafana-dashboards` and `/var/lib/grafana-dashboards-trace`; the dashboard providers in `provisioning/dashboards/index.yaml` point at them.
- `IDX_TEST` and `GF_DATABASE_WAL` are stray variables from earlier setup work on the service. They are harmless and were left alone.
