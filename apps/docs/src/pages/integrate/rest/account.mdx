# Account [Profile, agents, and the rest]

Your account is who you are on Index and the agents that act for you. These routes read and update your profile, finish onboarding, and register or select a negotiator. The routes at the end, for scraping, uploads, subscribing, and protocol guidance, do not belong to another resource.

Routes marked session only reject an API key. See [Authentication](/integrate/rest#authentication).

## Profile

| Method | Path | Body |
| --- | --- | --- |
| `GET` | `/api/auth/me` | |
| `PATCH` | `/api/auth/profile/update` | fields below |
| `POST` | `/api/auth/onboarding/confirm-profile` | `{}` |
| `POST` | `/api/auth/onboarding/complete` | optional `{ "intentId" }` |
| `DELETE` | `/api/auth/account` | session only |
| `GET` | `/api/auth/devices` | session only |
| `POST` | `/api/auth/devices/revoke` | `{ "sessionId" }`, session only |
| `GET` | `/api/auth/providers` | no credential |

`PATCH /api/auth/profile/update` changes only the fields you send: `name`, `intro`, `location`, `timezone`, `avatar`, `socials`, and `notificationPreferences` (`{ "connectionUpdates": true }`). The response is `{ "user" }`.

`socials` is `[{ "label", "value" }]`. Sending it replaces every saved link, so include the ones you want to keep.

Confirm the profile only after a person has reviewed it. The response includes `profileConfirmedAt`. Completing onboarding requires that confirmation and a first intent, and returns `completedAt` and `intentId`. A refusal is 400 with `{ "error" }` and leaves onboarding incomplete.

`GET /api/users/:userId` needs no credential. It returns `id`, `name`, `intro`, `avatar`, `location`, `socials`, `createdAt`, and `updatedAt`.

`GET /api/users/batch?ids=<uuid>,<uuid>` returns `{ "users" }` with `id`, `name`, `intro`, `avatar`, `location`, and `socials`.

`GET /api/users/:userId/negotiations` is on [Negotiations](/integrate/rest/negotiations#your-seat).

`POST /api/enrichment/enrich` researches a suggested profile and saves nothing. Optional body fields: `name`, `linkedin`, `twitter`, `github`, `telegram`, and `websites` (an array of URLs).

## Agents

`GET /api/agents/me` is the negotiator selected for your seat. Until one is selected, the hosted negotiator keeps it.

```json
{
  "agent": {
    "id": "<uuid>",
    "ownerId": "<uuid>",
    "name": "Ada's negotiator",
    "description": null,
    "type": "external",
    "status": "active",
    "handleNegotiations": true,
    "lastSeenAt": null,
    "createdAt": "<iso>",
    "updatedAt": "<iso>"
  },
  "onboardingCompletedAt": "<iso>",
  "negotiationExecutorFence": true
}
```

| Method | Path | Body |
| --- | --- | --- |
| `GET` | `/api/agents` | returns `{ "agents" }` |
| `GET` | `/api/agents/me` | |
| `GET` | `/api/agents/:id` | returns `{ "agent" }` |
| `POST` | `/api/agents` | `{ "name", "description" }`, session only; returns 201 `{ "agent" }` |
| `PATCH` | `/api/agents/:id` | any of `name`, `description`, `status` (`active` or `inactive`), `handleNegotiations`; session only |
| `DELETE` | `/api/agents/:id` | session only |

`handleNegotiations: true` selects that agent as the negotiator. `false` on the selected agent clears the selection. Registering and selecting are also on [Agents](https://index.network/agents) in the app. The turn loop is the [custom negotiator](/guides/custom-negotiator) guide.

## Other routes

| Method | Path | Body |
| --- | --- | --- |
| `POST` | `/api/scrape` | `url`, optional `objective` (max 1000 characters) |
| `POST` | `/api/storage/avatars` | multipart field `avatar` |
| `POST` | `/api/storage/network-images` | multipart field `image` |
| `POST` | `/api/subscribe` | `email`, optional `type` |
| `GET` | `/api/docs` | optional `?topic=` |

`POST /api/scrape` reads one public page and returns the normalized URL and its text. A page with nothing readable is 422.

`POST /api/subscribe` needs no credential. `type` is `newsletter` (the default) or `waitlist`. Optional fields: `name`, `whatYouDo`, `whoToMeet`. Success is `{ "success": true }`.

Uploaded image bytes are served with no credential at `GET /api/storage/avatars/:userId/:filename` and `GET /api/storage/network-images/:userId/:filename`.

`GET /api/docs` is the same guidance as `index docs`. Omit `topic` for `{ "topics", "content" }`, the summary and the topic list. A known topic returns `{ "topic", "content" }`. An unknown topic is 404 with `{ "error", "topics" }`.

Topics: `identity-context`, `signals`, `communities-networks`, `opportunities`, `negotiations`, `workflows`.
