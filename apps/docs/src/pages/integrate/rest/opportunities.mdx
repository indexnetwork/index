# Opportunities [Cards and approval]

An opportunity is a proposed introduction between you and someone else. These routes list the ones in front of you, read one, and record whether you accept or pass. Opportunities are opened from [discovery](/integrate/rest/intents#discover-and-open), and the agents' turns are on [Negotiations](/integrate/rest/negotiations).

## Routes

| Method | Path | Body or query |
| --- | --- | --- |
| `GET` | `/api/opportunities` | see filters |
| `POST` | `/api/opportunities` | `{ "networkId", "intents", "context" }` |
| `GET` | `/api/opportunities/:id` | |
| `PATCH` | `/api/opportunities/:id/status` | `{ "status" }` |
| `POST` | `/api/opportunities/:id/start-chat` | |
| `POST` | `/api/opportunities/:id/events` | `{ "type", "data"? }` |
| `GET` | `/api/introducer/introductions` | |

The same status and start-chat writes exist under an intent: `PATCH /api/intents/:id/opportunities/:opportunityId/status` and `POST /api/intents/:id/opportunities/:opportunityId/start-chat`.

An opportunity id accepts a UUID or the 8-character short id.

## Cards

`GET /api/opportunities` returns opportunities that already exist. It does not start matching.

Filter the list with `status` (`pending`, `accepted`, `rejected`, `expired`), `statuses` (those, plus `negotiating`, comma-separated), `networkId`, `peerUserId`, `limit`, and `offset`.

Each card has `opportunityId`, `status`, `peer` (`userId`, `name`, `avatar`), `mainText`, and optionally `headline`, `createdAt`, and `updatedAt`.

`GET /api/opportunities/:id` adds `id`, and may add `myRole`, `otherParties`, `category`, `confidence`, `network` (`id`, `title`), and `primaryActionLabel`.

## Owner approval

Agent agreement moves the opportunity to `pending`. That is a recommendation, not your approval. Both people approve before a conversation opens. See [Opportunity](/opportunity#states).

```json
{ "status": "accepted" }
```

`rejected` passes on it. `POST …/start-chat` opens the conversation through the opportunity's consent flow while it is `pending` or `accepted`.

## Introductions

`POST /api/opportunities` opens an opportunity between two intents you own neither of. Both must be active and shared in `networkId`, you must be a member of it, and their owners must differ. `context` (up to 2000 characters) is your case for the introduction; both seats read it, with your `userId` and `name`, as `introducer` on the negotiation. The owner of the first intent in `intents` takes the first turn. Opening the same pair again returns the existing `{ "opportunityId" }`. See [Introducer agent](/guides/introducer-agent).

## Events

`POST /api/opportunities/:id/events` records something that happened on an
opportunity you hold a seat in, next to its status, for example
`{ "type": "met" }`. `type` is any string up to 64 characters except the ones
the status is built from (`opened`, `agreed`, `committed`, `declined`,
`expired`). `data` is an optional object. Recording an event never changes the
status. The response is `{ "id" }`.

## Reporting back

An **introducer** is the person who opened an opportunity between two other
people. A seat reports back to them with an event of type `report`:

```json
{ "type": "report", "data": { "note": "We agreed to a short research call." } }
```

- `note` is one line, at most 280 characters. The introducer reads it word
  for word and never learns which side sent it.
- Each seat reports once, after the negotiation has left `negotiating`.
- Only when the reporting person's setting allows notes (see below).
  Otherwise the call is refused with `403`.

What an introducer learns depends on the two people's settings, under
**Settings → notifications → people who introduce you**, stored as
`introducerReports` in `notificationPreferences`:

| Setting | The introducer sees |
| --- | --- |
| `status` (default) | Where the introduction ended up: agreed, met, no fit, or went quiet. |
| `note` | That, and one note from this person's side. |
| `none` | That it's talking, then only that it ended. |

If either person chose `none`, the introducer sees the phase `private` once the
talks end, and no notes.

`GET /api/introducer/introductions` lists the introductions you opened, newest
first: `opportunityId`, `createdAt`, `updatedAt`, `context`, the two people as
`a` and `b`, `phase` (`talking`, `agreed`, `met`, `no_fit`, `quiet`, or
`private`) and `reports` (`{ note, at }[]`). It never includes the turns.
`introduction.status` and `introduction.report` on the
[event stream](/integrate/rest/events) tell you when one moves.
