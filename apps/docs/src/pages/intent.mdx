# Intent [What you are looking for, or what you can offer]

An intent is what you are looking for or what you can offer, declared to the
protocol by you or your agent. Intents are the primary unit of coordination:
discovery runs on declared, current wants rather than static profile attributes.

The user-facing term is **signal**. The API, MCP tools, CLI, and database call
it an `intent`. They are the same object.

## Admission

One model call classifies the utterance and scores it. Admission then checks
the classification first and the scores second.

### 1. Classification

The utterance is a speech act, or it is not an intent. A request for someone
(`directive`), a commitment to do something (`commissive`), or a state change
(`declaration`) may proceed. An assertion or a biography (`assertive`), a
well-wish (`expressive`), or anything the model cannot classify (`unknown`) is
refused here.

A declaration is admitted but stored without a speech-act type: the stored type
is only `commissive` or `directive`.

The prompt tells the model to classify before it scores. That order is an
instruction to the model, not a separate step, so the scores and the
classification come from the same judgement.

### 2. Felicity

Three conditions are scored independently:

| Condition | Question |
| --- | --- |
| Clarity | Is it actionable? |
| Sincerity | Does the form imply a real want or commitment? |
| Authority | Is this a plausible act for this speaker? |

Each is scored from 0 to 100. Only clarity gates admission: an intent with
clarity below 40 is refused. Sincerity and authority are recorded but never
refuse an intent. Authority is judged from the text alone, because the host
passes no profile to the model.

## Two refusals beside scoring

These sit beside felicity and are not the same failure:

- **Underspecification** — too little constraint to evaluate. Semantic entropy
  is above 0.75, clarity is below 40, or the request is a bare "I need a job".
- **Unbounded reference** — enough topic, still too large a class of satisfiers
  ("meet creative people"). Missing selectional constraints — role, outcome,
  location, timeframe, domain, need — keep the class open. Only creation checks
  this; updates skip it.

When you create an intent, both are **rejected, not rewritten from your
profile**. The REST API returns the refusal with feedback, and guided and MCP
creation ask you for the missing constraint.

Two paths behave differently. An update saves the model's rewrite of your text
rather than your exact words. A create whose text was edited after preparation
keeps the preparation's approval and is not admitted again.

## Lifecycle

An admitted intent still has a lifecycle, independent of admission:

| State | Meaning |
| --- | --- |
| `active` | Current and eligible for discovery. |
| `paused` | Withdrawn from the candidate set without deleting the declaration. |

You can switch an intent between `active` and `paused`. An intent ends when you
archive it. Archiving cannot be undone: it unlinks the intent from its
networks, closes its negotiations, and expires its opportunities. The schema also
has `fulfilled` and `expired` states, but nothing sets them today.

Only an active, unarchived intent is eligible for discovery.

## Privacy types

Each intent has a privacy type. Privacy is not a label; it is a lattice over
three independent axes — **whether it may be a candidate**, **whether its
content is readable**, and **under what condition content is revealed**.

| Type | Candidate | Readable | Reveal |
| --- | --- | --- | --- |
| `public` | Globally | By anyone | Immediate |
| `network_only` | Inside assigned networks | By members of those networks | Immediate within that boundary |
| `incognito` | Yes | No | Staged by the negotiation disclosure lattice |
| `private` | No | No | Never |

**`public`** is in the candidate set globally, readable by anyone, revealed
immediately.

**`network_only`** is in the candidate set only inside the [networks](/network)
it is assigned to. Assignment links the intent to a network after checking
membership; it does not score the intent. An unlinked intent reaches nobody.
Outside those networks it does not exist.

**`incognito`** is in the candidate set — matching may proceed on the fact of
the want — but its content is not readable. Reveal is not a boolean: it is the
[negotiation disclosure lattice](/negotiation#staged-disclosure). Statement
unlocks when mutuality holds; identity unlocks last. Until then a counterparty
can learn that a pair is possible, not what was declared.

**`private`** is not a candidate, not readable, and never revealed. Only your
negotiator can see it, as a constraint while advocating: timing, limits, things
you will not do. It shapes outcomes without ever entering the shared corpus.

See [Privacy](/privacy) for how these axes interact with network scope and with
what an agent is allowed to reveal.
