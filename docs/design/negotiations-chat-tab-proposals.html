The Negotiations tab in /chat

With the first-class inbox shipped (PR #1232, merged), the remaining surface is the Negotiations tab inside the chat sidebar — the Messages / Negotiations toggle in ChatSidebar.tsx. It still runs its pre-inbox logic. This document assesses what it does today, then recommends what it should become: an ambient view over the same lifecycle projection, not a second triage surface.

P1

The emerald dot lies

Last action accept → green "Accepted" dot (ChatSidebar.tsx:96-99). But agent accept only moves the opportunity to pending — no human has accepted anything. The one color that reads as "done" actually means "waiting on you". This is exactly the three-status-layer conflation the domain docs warn against.

P2

"Your move" is invisible

ask_user consultations (with a 24h window) and agents-agreed outcomes get no badge, no pill, no ordering priority. The tab cannot answer the only question that matters in passing: do I owe my agent something?

P3

Two derivations, one truth

The sidebar re-derives status inline from the last DataPart action, while the shipped deriveNegotiationInbox() (lib/negotiation-inbox.ts) already classifies the full lifecycle — task state, opportunity status, outcome reason, viewer attribution. Two interpretations of the same data will drift; the naive one is already wrong on stalled, screened_out, and zero-turn shells.

P4

Small frictions

Empty state says "No messages yet" in Negotiations mode (:178 — same copy as Messages). Resolved rows aren't visually retired. The hover menu offers "Delete" on an agent transcript — destructive-sounding for what is really "hide".

§1

The tab's job — ambient, not triage

The inbox owns triage and action. The /chat tab owns a different moment: the user is already in their messages and wonders "anything moving?". That makes it a watch + jump-off surface — glanceable in two seconds, one tap from wherever the action actually lives. Everything below follows from that split.

  • A1 · One classification sourceConsume the shipped deriveNegotiationInbox() and delete the sidebar's inline derivation. Whatever the inbox believes, the tab believes — no drift, no second opinion.
  • A2 · Labels, not dotsA chip can say "Live · turn 3 of 6" or "Answer your agent". A dot can only say amber. Status text wins in a rail this narrow.
  • A3 · Flat list, priority orderNo group headers in a 320px rail. One list ordered your-move → live → waiting → resolved, with hairline dividers between posture runs. Resolved rows visually retired (the inbox's opacity-80 idiom).
  • A4 · Every row one tap from its action surfaceAnswer rows go to the negotiator DM (a transcript can't take an answer). Agreed rows go to the transcript's review affordance. Everything else goes to the transcript at /chat/:id, as today.
  • A5 · Free livenessConversationContext.negotiations already refreshes over SSE. The tab inherits live updates; only live rows get the amber pulse, same idiom as the inbox.
  • A6 · Don't rebuild the inbox hereNo group sections, no CTAs, no turn-progress bars in the rail. A persistent "View all in inbox" footer routes real work to the right place.

Recommendations

R1 Single source of truth ChatSidebar.tsx consumes lib/negotiation-inbox.ts

Replace the inline last-action derivation (ChatSidebar.tsx:84-114) with deriveNegotiationInbox(negotiations, user?.id) — the same function the inbox page and the TopBar pill already use. Every surface reads one projection.

R2 Row anatomy — chips, posture order, retired resolved the tab list itself

Keep the row skeleton (avatar 28, name, subline, time — users know it), but swap the dot for the inbox's compact status chip, order by posture with hairline dividers, mute resolved rows, and fix the preview line to use the lib's describeAction/describeResolved phrasing instead of a raw reasoning fragment.

Put a navy count pill on the Negotiations toggle itself, fed by the shipped countNegotiationsRequiringAction(): the number of your-move items (answer + agreed), hidden at zero. Even from the Messages side of the toggle — the default view every user actually lives in — "do I owe my agent something?" is answered without switching tabs.

R4 Row targets — one tap to the right surface navigation behavior per status

Today every row opens the transcript. Right for most states — wrong for the two that need a human. Route by status:

The transcript is read-only by design; sending an "Answer your agent" row there is a dead end. If the negotiator DM deep-link is more than a route change, ship R4 in a second pass and keep transcript links as the interim target.

R5 Mode-aware empty state sidebar empty copy

Fix the "No messages yet" copy that currently shows in Negotiations mode, and use the moment to teach the feature rather than just report emptiness.

R6 Alternative considered: grouped mini-inbox in the rail not recommended (for now)

A heavier variant: pin a "Your move · N" section header inside the tab, mirroring the inbox's grouping in miniature. Rejected for three reasons: it duplicates triage in a space too narrow to act (no room for CTAs), it splits attention between two surfaces that would then both "own" your-move, and R3's toggle badge already surfaces the same signal without the furniture. Revisit only if negotiation volume grows to the point that the flat list regularly scrolls your-move items out of view — at which point the right answer is still "go to the inbox", one tap away in the footer.

§3

Implementation shape

Everything here is presentation-layer over data and logic that already shipped in PR #1232. No API changes, no new endpoints, no new dependencies.
