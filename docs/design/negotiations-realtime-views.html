§2

The information the user actually needs in passing is: state (chip), momentum (turn N of M + who moved last), stakes (mutual signals), and what I get out of it (my negotiated role once agreed). Two densities are credible; pick per taste, both beat the dot.

§3

/negotiations — two view modes, both live

The grouped view answers "what do I owe?" — the recent view answers "what moved?". Add a segmented Grouped / Last updated toggle under the header (same control idiom as the chat sidebar), persist the choice in localStorage, and keep both modes live over the existing SSE stream.

Grouped mode is today's page, unchanged. Last updated mode is the same rows in one flat list ordered by lifecycle.updatedAt descending — group affiliation stays visible as the chip, so nothing is lost; it's a resort, not a different page. New arrivals and state changes animate in place (see §4).

Realtime rules (both modes)

R1 · The plumbing exists — use it

Every SSE message event already calls refreshNegotiations() (ConversationContext.tsx:358) and the page derives via useMemo. Updates land without reload today; they just land silently and coarsely.

R2 · Flash, don't teleport

Changed rows get a 1.6s highlight: amber-tinted for content updates (a turn landed), steel-tinted for posture moves (waiting → your move). In Last-updated mode, moved rows animate to their new position instead of vanishing/reappearing (stable keys + transform transition).

R3 · Debounce the stream

The current code refetches the whole list on every SSE message event. Batch with a ~500ms trailing debounce so a 3-turn burst revalidates once, not three times. Even better later: apply the event payload to the summary in place and refetch only on unknown ids.

R4 · Show the connection

isConnected is already in the context. A small "live" dot in the header (emerald) flips to gray "reconnecting…" on drop — realtime you can't trust is worse than none.

R5 · Timestamps tick

timeAgo strings are computed at fetch time. Re-render them on a 30s interval so "just now" doesn't freeze for the life of the page.

R6 · Preserve local state

Refetches replace the list array; keyed rendering must preserve scroll position, hover, and any expanded row. Nothing the user is looking at may jump while they read it.
